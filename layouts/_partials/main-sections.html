{{- /* main-sections.html — the single resolution of site.Params.mainSections. Returns a lowercased, whitespace-trimmed slice: the configured value, or (slice "archives" "posts") when the site configures none. Guarantees, each of which a consumer may rely on: - always a slice (a scalar `mainSections = 'posts'` is legal config and is coerced; `in` against a STRING set is a substring test, not membership); - every entry lowercased and trimmed, because Hugo reports .Section lowercased — `['Notes']` and `[' notes ']` would otherwise compile fine and then match nothing, silently costing a section its year pills; - an empty value is treated as unset, which is what a site with no main sections wants: the union in is-list-section.html still treats /posts/ and /archives/ as list sections regardless of this param, so [] could never have meant "no list sections". `isset` cannot distinguish the two here — it returns false for a configured ['posts'] as well as for []. It exists because this param was read in five places, each with its own `default`, and the copies had already diverged in a way that shipped: the list page widened its set to the literal "archives"/"posts" names while the single templates gated on plain membership, so a post under /posts/ got year pills from one page and no breadcrumb or post-meta from the other. One definition, called from all of them. Measurements behind the above were taken on Hugo 0.146.0 and 0.166.0; re-run them before changing this partial rather than trusting the numbers in the PR history, which rot as Hugo moves. */ -}} {{- $mainSections := site.Params.mainSections -}} {{- if not $mainSections -}} {{- $mainSections = slice "archives" "posts" -}} {{- else if not (reflect.IsSlice $mainSections) -}} {{- $mainSections = slice $mainSections -}} {{- end -}} {{- $normalized := slice -}} {{- range $mainSections -}} {{- $normalized = $normalized | append (lower (trim . " \t")) -}} {{- end -}} {{- return $normalized -}}
