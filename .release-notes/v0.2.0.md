### Lesson — `$.Site.Taxonomies.categories` for category term lookup

`.Site.Taxonomies.categories` (plural) is a `map[term-slug][]Page` index of every category term across the site. To resolve the display title for a single term slug from a `.Params.categories[0]` value:

```go-html-template
{{- $termSlug := index .Params.categories 0 -}}
{{- $termEntry := index $.Site.Taxonomies.categories $termSlug -}}
{{- $displayTitle := $termSlug -}}  {{/* fallback */ -}}
{{- with $termEntry -}}
  {{- with index . 0 -}}
    {{- $displayTitle = or .Title $displayTitle -}}
  {{- end -}}
{{- end -}}
```

This is faster and less error-prone than the old `$term` / `$termPage` range-block pattern, which broke when the lookup happened outside a `{{ range . }}` block — the scope error swallowed the entire build silently (Hugo just rendered `\n\n`). All four template files (`post-card.html`, `single.html`, `posts/single.html`, `archives/single.html`) now share the same pattern, so behavior stays consistent across surfaces.

### Lesson — Page bundle covers via `Resources.GetMatch`

`$.Page.Resources.GetMatch name` returns the actual page-bundle resource (with `.RelPermalink` pre-resolved to the fingerprinted asset URL). When `og:image` / `twitter:image` reads `.Params.cover`, calling `$.Page.Resources.GetMatch` first handles page-bundle covers cleanly:

```go-html-template
{{- $ogImage := "" -}}
{{- with .Params.cover -}}
  {{- if not (or (hasPrefix . "http://") (hasPrefix . "https://")) -}}
    {{- if not (hasPrefix . "/") -}}{{ $.Params.cover = printf "/%s" . }}{{- end -}}
  {{- end -}}
  {{- $ogImage = . -}}
{{- end -}}
{{- $ogImage = default "og.svg" $ogImage | absURL -}}
```

Combined with `5aa48cb`'s per-page front-matter read, all three sources now resolve correctly: page-bundle cover → static-path cover → `og.svg` fallback. The "my cover image never shows in social previews" bug class is fully closed.

### Lesson — Explicit `slice` + `Concat`, not `resources.Match`

The v0.1.9 release used `resources.Match "css/components/*.css"` to auto-pickup every component file. `Match` returns files in alphabetical order, which **broke cascade order**: `_tokens.css` (CSS custom properties) landed AFTER the component files that consumed those variables. The browser then re-declared the variables at the bottom of the bundle, and home-page layout collapsed to ~980px centered because component-specific tokens got clobbered by the late-arriving `_tokens.css`.

Three fixes baked into v0.2.0:

- **`$stylesheets := slice (...)`** — explicit slice in `layouts/_partials/head.html` with components listed in the exact cascade order. `resources.Concat "css/main.min.css" | resources.Minify | resources.Fingerprint` produces a single `<link rel="stylesheet" href="/main.min.<hash>.css">` — same HTTP request count, same cache-key strategy.
- **Numbered cascade-order comment block** at the top of the slice. A PR that adds a new component file has to update both the slice AND the comment — diff review catches accidental reordering.
- **`main.css` kept as 685-line canonical reference** of the pre-split monolithic source. Future re-splits can diff against it to verify byte-for-byte equivalence (verified during this release: split-output fingerprint matches pre-split monolithic fingerprint).

Trade-off: adding a new component now requires a two-step edit (drop the file in `assets/css/components/` AND append to the slice AND update the numbered cascade comment), instead of zero-config `Match` auto-pickup. Worth it — silent build-pass-with-wrong-output is the worst kind of regression.

### Requirements

- Hugo Extended **0.146.0** or newer (unchanged from v0.1.9).
- Categories alongside tags: zero config — drop `categories = ["webdev"]` into a post's front matter and the theme renders the term page's `.Title` (e.g. `建站`) automatically. Override per-term via `content/categories/<slug>/_index.md`'s `title:` field. Falls back to the hardcoded `webdev → 建站` mapping, then to the raw slug.
- `og:image` / `twitter:image`: zero config — set `cover: "images/foo.png"` in front matter and the meta tags use that file. Falls back to `/og.svg` for pages without `cover`. Bundle covers (drop `cover.jpg` into the page bundle, leave `cover:` blank) also resolve via `Resources.GetMatch`.
- Cover-image caption pill: opt-in via `cover_caption: "..."` in front matter. Empty (default) → no `<figcaption>` rendered.
- Friends page: zero config — drop a `content/friends/` page bundle with the expected data shape and the styled page renders automatically. Style lives in `assets/css/components/friends.css` (slot 13 of the bundle).
- Opt-in highlight.js: opt-in via `[params] highlight = 'hljs'` in `hugo.toml`. Sites not setting it see zero change (zero chroma bytes shipped unless you opt in).
- Tested on Hugo 0.165.0.
