Feature release: bilibili + youtube video embed shortcodes (privacy-enhanced domains, tracking-stripped, responsive 16:9), inline image caption pill style with dark-glass backdrop-blur (matching the `cover-caption-pill` pattern), a `layouts/ja/single.html` for the JA section, restoration of the post-meta layout (word count + page views + meta-pills outside post-meta), and a `lastmod` display fix so newly-published posts still show "更新于".

### Highlights

- **Bilibili + YouTube embed shortcodes** — Two new shortcodes mirroring the site-level ones in `hansen-blog`, so any project using the Lumenveil theme gets embed support out of the box:

      {{< bili BV1xx411c7mH >}}       -- bare BV short ID
      {{< youtube dQw4w9WgXcQ >}}     -- bare YouTube video ID

  Shared design principles:

  - Accept the platform's native short ID (BV for bilibili, 11-char video ID for youtube). Tracking params (`share_source`, `vd_source`, `si`, `feature`, `pp`, …) are intentionally stripped — only the ID is forwarded to the player, so the shortcode works for any current and future ID without code changes.
  - Full URLs auto-extract the ID via regex (`watch?v=`, `youtu.be/`, `/shorts/`, `/embed/` for youtube; matching shapes for bilibili).
  - Responsive 16:9 iframe, `loading="lazy"`, rounded corners, dark placeholder, soft shadow.
  - **Official privacy-enhanced domains:** `player.bilibili.com` and `youtube-nocookie.com`. YouTube's `nocookie` variant sets no cookies until the user actually hits play; `rel=0` hides unrelated recommendations after the video ends.
  - Optional params: page number (bilibili), start seconds (youtube), autoplay flag (both), `high_quality` (bilibili).

  YouTube ID regex is `[A-Za-z0-9_-]{10,12}` to stay backward-compatible with the legacy 10-char IDs (e.g. `e1J84WMI6k`) that predate YouTube's 2010 standardization to 11 chars. Both shortcodes use inline styles on a single container (`.bili-embed` / `.youtube-embed`) — no CSS component file needed, so the components slice stays untouched. Commit `f97ca52`. Docs `36fbf9f` adds a new `### Video embed shortcodes` README section covering usage, URL forms, and per-shortcode params.

- **Inline image caption gets the same dark-glass pill as cover captions** — Markdown's standard `![alt](img)` + `*caption*` pattern (which Hugo renders as standalone `<figure>` + a separate `<p><em>caption</em></p>`) now gets the same dark-glass pill treatment as `.cover-caption-pill`: centered below the image, dark backdrop-blur background, rounded full border, small text. The selector `.prose p > em:only-child { display:inline-block; … }` scoped to `.prose` so it only fires on the markdown pattern, not on every italic in the article body. Before: `*画像出典：[七ツ森りりの X](https://x.com/riri_nntmr)*` rendered as plain left-aligned `<em>`. After: same content, but as a centered pill below the image. Commit `878f6a6`.

- **JA section gets its own `single.html` layout** — Pages with `type: page` + `section: ja` (used by the Japanese section of `hansen-blog`) previously fell through to `layouts/page/single.html` which has no cover and no TOC. New `layouts/ja/single.html` mirrors `archives/single.html` structure: `partial "cover.html"` for the cover, `if .TableOfContents` + `if ne .Params.toc false` conditional TOC aside, proper breadcrumbs (`首页 / 記事 / {{ .Title }}`), and the post-meta bar scoped to `{{ if eq .Section "archives" }}` so it only renders for archive pages within the JA section. Scoped to `section == "ja"` so it doesn't affect other page types (about, friends, etc.). Commit `0b66c20` (preserved via the merge-commit tree at `7d5b4fd`).

### Bug fixes

- **Restore post-meta layout (revert broken meta-pills fix)** — Commit `eceadfa` ("Fix archives/single meta-pills template") rewrote the meta-pills block in `layouts/archives/single.html`, moving category/tags pills inside the `post-meta` div and silently dropping `{{ .WordCount }} 字` and the busuanzi `阅读 X 次` span. Net result on `hansen-blog`: date + reading-time on row 1, then a single line with `category · tag · category · tag` (no separator bar), and **no** 字数 / 阅读次数 anywhere. The pre-`eceadfa` layout (date · reading time · 字数 · 阅读次数 on one line, with category/tags pills on the next line as their own `meta-pills` block) is restored. Category pill still uses the term page Title with fallback (unchanged from v0.2.0). Commit `7d787d2`.

- **`lastmod` display when `lastmod == date`** — Previous condition `gt .Lastmod .Date` (strictly after) silently dropped the "更新于" line for the common "just published, no edits yet" case where front-matter sets `lastmod` equal to `date`. The bar then showed only "发布于" with no last-touched signal — confusing because the post *was* touched at that moment, even if the touch was the publish action. Changed to `ge` (greater-than-or-equal) so any non-zero lastmod renders. Docstring updated from "(only if strictly after Date)" to "(only if Lastmod >= Date)". Commit `608df51`.

- **Inline caption pill — 3 follow-up CSS iterations** — Three iterations were needed after `878f6a6` to land the centering reliably across browsers. `0e25b26` swapped `display:inline-block` for `display:table` so `margin:auto` actually centers the pill (per CSS spec, `auto` margins resolve to `0` on inline / inline-block). `5480ff0` then switched to `:has()` + `text-align:center` on the parent `<p>` — more reliable for inline content because the inline-block em centers inside the text flow. `6078869` corrected the selector from `:has(>figure+em)` to `:has(>em:only-child)` — the old selector targeted `<p><figure/>+<em></p>` which Hugo never produces (caption renders as standalone `<figure>` + separate `<p><em>caption</em></p>`), so the rule had existed since `5480ff0` but never matched anything and inline captions rendered without pill styling. The new selector targets actual Hugo output: a `<p>` whose only child is `<em>`. Net diff of the four-commit arc: 22 lines added to `assets/css/components/article.css`, ~7 lines deleted; one selector change, two display-strategy changes, one selector correctness fix.

### Lesson — Find the actual Hugo output before writing a selector

The four-commit arc above (`878f6a6 → 0e25b26 → 5480ff0 → 6078869`) is a textbook case of "select what Hugo produces, not what you think it produces." The first version of the selector (`:has(>figure+em)`) matched the conceptual model ("image followed by italic caption in same paragraph") but not Hugo's actual HTML output. The fix wasn't to make the selector more clever — it was to inspect what Hugo emits (`<figure class="pswp-figure">` standalone + separate `<p><em>caption</em></p>`) and target that.

Practical pattern: when a CSS rule "isn't working" and you're confident the logic is right, open the rendered HTML in DevTools and confirm the structure. The mismatch is almost always between mental-model and actual-output, not between selector and intent.

### Lesson — Three reliable ways to center inline content

The three CSS iterations above also gave us a clean taxonomy of inline-content centering strategies:

| Strategy | Selector | Trade-off |
|---|---|---|
| `display:table + margin:auto` on the element itself | `.prose p > em { display:table; margin:8px auto; }` | Works in every browser; but the element must be wrapped in a block context, which table-display provides. Quirk: doesn't sit in the parent's text flow. |
| `display:inline-block + text-align:center` on the parent | `.prose p:has(>em:only-child) { text-align:center; } .prose p > em { display:inline-block; }` | Element stays inline; parent provides the centering via text-flow. Requires `:has()` (Chrome 105+ / Firefox 121+ / Safari 15.4+) — already the theme's baseline. **Preferred for prose content.** |
| `flex` on parent + `justify-content:center` | `.prose p:has(>em:only-child) { display:flex; justify-content:center; }` | Cleanest semantics, but converts the paragraph to flex layout — kills other inline content if the parent contains more than just the caption. Wrong tool for "caption-only paragraph." |

The current rule uses the second pattern. It's the most reliable across the browsers the theme already targets, keeps the em inside the text flow (so future inline siblings — like a credit link — would still render naturally), and doesn't disrupt the paragraph's outer layout.

### Lesson — Section-scoped templates override type-scoped templates

Hugo's template lookup order for a page with `type: page` is:

1. `layouts/page/single.html` (type-scoped)
2. `layouts/_default/single.html` (kind-scoped, fallback)
3. `layouts/_default/single.html` again (same)
4. Render as a plain content page

If you want different layouts per *section* (e.g. JA gets cover + TOC, but EN about page doesn't), drop a section-scoped file at `layouts/<section>/single.html`. Hugo's lookup checks section-scoped templates before type-scoped ones. So `layouts/ja/single.html` overrides `layouts/page/single.html` for any page whose `Section == "ja"`, with zero config and zero risk of affecting other page types. Same trick works for `layouts/posts/single.html` (already in use for the blog's post-type) and `layouts/archives/single.html` (already in use for archive-section posts).

### Requirements

- Hugo Extended **0.146.0** or newer (unchanged from v0.2.0).
- Bilibili / YouTube shortcodes: zero config. Drop `{{< bili BV1xx411c7mH >}}` or `{{< youtube dQw4w9WgXcQ >}}` into any markdown — full URLs auto-extract the ID.
- Inline image caption pill: zero config. Just use the standard `![alt](img)` + `*caption*` markdown pattern; the pill styling is automatic.
- JA section `single.html`: zero config. Pages with `section: "ja"` auto-route to `layouts/ja/single.html` instead of the generic `page/single.html`. Cover renders via `partial "cover.html"`, TOC renders if `Params.toc != false`.
- Post-meta restoration: zero config — already active on all `archives/single.html` pages.
- `lastmod` display: zero config — the `ge` condition is always-on; the bar now shows "更新于" for any post where `lastmod >= date`.
- Tested on Hugo 0.165.0.
