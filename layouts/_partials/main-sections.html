{{- /* main-sections.html — the single resolution of site.Params.mainSections. Returns the configured slice, or the literal (slice "archives" "posts") when the site sets none. Why this exists: `site.Params.mainSections` was read in five places (section.html, posts/single.html, single.html, ja/single.html, plus the per-template fallbacks) and every copy carried its own `default`. That is not a style preference — the copies already diverged once, and the divergence shipped: section.html widened the list set to include the literal "archives"/"posts" names so /archives/ keeps its year pills, while the single templates gated on plain membership, so on mainSections = ['notes'] a post under /posts/ got year pills and a card template from its list page but no breadcrumb, no post-meta and no post-nav from its own page. One predicate, one definition, called from all of them. */ -}} {{- $mainSections := site.Params.mainSections -}} {{- if not $mainSections -}} {{- $mainSections = slice "archives" "posts" -}} {{- else if not (reflect.IsSlice $mainSections) -}} {{- /* A scalar mainSections = 'posts' is legal config. Passed through raw it would reach `in $mainSections $section` as a STRING set, and `in` on a string is a substring test, not membership — a section named "post" would match. */ -}} {{- $mainSections = slice $mainSections -}} {{- end -}} {{- /* Normalise every entry against how Hugo actually reports sections: .Section is always lowercased. So mainSections = ['Notes'] or [' notes '] compiles fine and then silently matches nothing — the section keeps no year pills and no card template, with nothing in the build log. Measured on 0.166.0 against a /notes/ section: ['notes'] -> list, ['Notes'] and [' notes '] -> not a list section. Lower/trim here, once, so the predicate can stay a plain `in`. No type guard is needed for the elements. Hugo stringifies config scalars before a template ever sees them, so mainSections = [2024] arrives here as []string{"2024"}, and trim/lower are safe. A nested slice arrives as []string{} — empty, so the documented default branch above applies and `in` never sees a non-string. Verified on 0.166.0. */ -}} {{- $normalized := slice -}} {{- range $mainSections -}} {{- $normalized = $normalized | append (lower (trim . " \t")) -}} {{- end -}} {{- return $normalized -}}
